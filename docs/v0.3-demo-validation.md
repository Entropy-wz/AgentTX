# AgentTx v0.3 Demo Validation

This document describes the v0.3 functionality validation bundle.

The goal is demo-grade verification: one command should produce a readable report, metrics, capability coverage, and transaction evidence. It is not the final paper-scale experiment and does not add new AgentTx research features.

## Run

```powershell
npm run validate:v0.3-demo
npm run check:v0.3-demo
npm run package:v0.3-demo
```

The generated output is written to:

```text
validation/v0.3-demo/<run_id>/
```

The packaged bundle is written to:

```text
release/agenttx-v0.3-demo-validation-<run_id>.zip
```

## Output Files

| File | Purpose |
|---|---|
| `experiment-manifest.json` | Run metadata, command results, and experiment step results |
| `capability-matrix.json` | Capability-to-experiment coverage |
| `artifact-index.json` | Pointers to copied evidence artifacts |
| `mini-benchmark-summary.json` | Six-case mini benchmark output |
| `ablation-summary.json` | Five-baseline ablation output |
| `metrics.json` | SRR, REC, FBR, TCR, ASR, AOS, AOS_WARN, and MISALIGN |
| `validation-report.md` | Human-readable validation report |
| `function-coverage.md` | Capability coverage table |
| `transactions/` | Copied transaction and runtime evidence |
| `raw/` | Raw benchmark, ablation, metric, and command logs |

## Experiment Steps

| Step | Capability demonstrated |
|---|---|
| E0 plugin validate | Claude Code plugin package is loadable |
| E1 dangerous Git block | CRITICAL command blocking and `command.blocked` evidence |
| E2 SAFE quiet check | SAFE commands are allowed without Memory Capsule or Alignment Warning |
| E3 file delete recovery | `filesystem.delete`, `restore_file`, and verifier recovery |
| E4 env credential modify | `env.modify`, `credential.modify`, blocking recovery |
| E5 package graph recovery | `package.modify`, dependency edge, graph recovery plan |
| E6 service config mock | `service.config.modify` without claiming real service recovery |
| E7 external residual mock | `external.network` residual warning and warning alignment |
| E8 belief pollution repair | belief repair, clean summary, taint propagation |
| E9 runtime contract | package-failure runtime contract and verification flow |
| E10 baseline ablation | comparison against no defense, human confirmation, snapshot-only, and no belief repair |
| E11 AOS summary | observable OS state plus externalized belief consistency metric |

## Metrics

| Metric | Meaning |
|---|---|
| `SRR` | State Recovery Rate |
| `REC` | Residual Effect Count |
| `FBR` | False Block Rate |
| `TCR` | Tainted Claim Rate |
| `ASR` | Agent State Repair |
| `AOS` | Agent-OS Observable Consistency |
| `AOS_WARN` | Aligned with residual warnings |
| `MISALIGN` | Missing or inconsistent alignment |

## Current Boundary

This validation bundle demonstrates observable workspace recovery and AgentTx-managed externalized belief repair.

It does not claim:

- OS-level sandboxing;
- full system rollback;
- real network capture;
- real service recovery;
- Claude hidden memory modification;
- Recovery Template Registry;
- Shadow Workspace execution.
